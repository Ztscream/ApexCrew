# ApexCrew M1-M4 Implementation Plan

> **For agentic workers:** Execute the S1-S22 tasks from `SPRINT.md` in order, with observed red tests, minimal implementations, ordered spec and quality checks, and one Conventional Commit per task.

**Goal:** Make the approved ApexCrew harness runnable end to end through M4 while preserving fail-closed security boundaries and clearly labeling skeletons and stubs.

**Architecture:** Extend the existing A-Hybrid core through narrow domain contracts, durable state adapters, repository and executor adapters, and CLI/query projections. The local CLI remains the only mutation surface; the WebUI is a sanitized read-only replay. `ScriptedMockLLM` is the deterministic default, while the OpenAI adapter is a non-calling thin seam.

**Tech Stack:** Python 3.12, Pydantic, SQLite, Typer, FastAPI/Jinja2, pytest, Ruff, mypy, Docker, GitHub Actions, GitLab CI, and static HTML/CSS/JavaScript.

## Execution Rules

Every task records its base SHA and changed paths in `AGENT_LOG.md`, writes the failing test first, observes a red result, implements the smallest change, runs its focused green selector, then runs `uv run --python 3.12 mypy src`, `uv run --python 3.12 ruff check .`, `uv run --python 3.12 ruff format --check .`, and `git diff --check`. REAL tasks receive a spec-compliance self-review followed by a code-quality self-review; SKELETON and STUB tasks receive one self-check. Commits include `PLAN-Task`, `Subagent`, `Human-Changes`, `Spec-Review`, and `Quality-Review` trailers. `SPEC.md` is never edited, and push/PR/Pages enablement remain owner actions.

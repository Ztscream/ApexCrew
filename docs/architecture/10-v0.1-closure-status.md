# v0.1 闭环状态

更新于 2026-08-10。本页把可重复的本地实现证据与可对外宣称的交付状态分开记录，避免将“某个独立工作树的测试通过”误写成“root、远端 `main` 或 release 已通过”。

## 权威关系

- [`SPEC.md`](../../SPEC.md) 是产品、安全和验收语义的唯一规范，保持冻结。
- [`PLAN.md`](../../PLAN.md) 是 R4.3 的授权任务和完成账本；只有其 review/ledger 条目关闭，任务才是后续任务可依赖的权威基线。
- [`AGENT_LOG.md`](../../AGENT_LOG.md) 保存 red/green、修正与审查证据。
- 本页只说明截至日期可观察到的本地提交和未满足门禁，不改变上述记录。

## 状态词汇

| 状态 | 含义 | 不代表什么 |
| --- | --- | --- |
| 已完成双评审 | 实现、独立 SPEC review、独立 quality review 和 ledger closeout 都已完成 | 远端 CI、发布或生产可用 |
| 本地实现已绿，评审待完成 | 独立工作树中已有实现提交并观察到本地验证通过 | 已合入 root/`main`、可作为权威后续基线、PR 已合并 |
| 未开始 | 尚无该任务的实现与验证证据 | 设计或前置任务已经足够替代它 |
| owner-only 外部 gate | 需要仓库所有者授权的远端操作或外部环境观察 | 本地测试可自动替代的证据 |

## 最短闭环路径

R4.3 的依赖顺序不能通过并行合并跳过。最短路径是：

1. 依次为 R4.3-04、R4.3-05、R4.3-06 进行 owner-independent SPEC review，再进行独立 quality review；修复 Critical/High 问题，并在 `PLAN.md` 和 `AGENT_LOG.md` 关闭每个 task 的 ledger。
2. 从完成 R4.3-06 closeout 的同一 revision 创建 R4.3-07 工作树，运行并记录同 SHA 的 `make test`、`make lint`、`make demo`、`make secret-scan`、`make web-build`、`make build`、性能、static replay 和 360/1440 CSS pixel WebUI 检查。
3. 由 owner 创建每个任务各自的 PR，观察该 SHA 的 Windows/Ubuntu CI 和 GitLab `unit-test`，随后按授权执行 merge、Pages 或 package publication。旧 PR 的绿色结果不覆盖 R4.3 增量。
4. 在支持的环境中观察一次真实 restricted Docker process，记录 daemon/image/process 结果，并同步 `README.md`、`SECURITY.md`、`SPRINT.md` 和 `AGENT_LOG.md` 后才可关闭 `DEBT-M2-005`。

## 证明边界

| 证据 | 可以支持的结论 | 不能支持的结论 |
| --- | --- | --- |
| 某独立工作树的 pytest、mypy、Ruff 和 diff check | 该提交在当前本地环境通过这些 selector | root/`main` 已通过、远端 CI 已通过、release artifact 已发布 |
| 两个 acceptance fixture 的最终 CAS 断言 | 该任务工作树中的 deterministic repair chain 受测试保护 | 任意模型或任意仓库能够自动修复问题 |
| frozen purge manifest 和 recovery selector | metadata-first purge 的本地行为符合该任务测试 | Tier 2 export 已启用，或所有 retention debt 已在 root 关闭 |
| release workflow 定义和本地静态检查 | 所需门禁被定义且可在本地验证一部分 | Windows/Ubuntu/GitLab runner 已对同一 SHA 给出成功结果 |
| 真实 Docker 进程观测 | 该环境的受限 Docker 路径实际运行过 | 其他平台、远端 CI 或 provider 行为自动等价 |

## 有意不做的范围

v0.1 仍只支持一个本地仓库、一个用户和最多三个 Worker。分布式队列、多租户、linked worktree、sparse/split index、shallow/partial history、外部 Git storage、Tier 2 export，以及多意图冲突的自动消解都不属于本次最短闭环。多意图无法唯一观测时仍停在 `INDETERMINATE`；malformed unified diff 继续复用 fail-closed scope-denial 结果码，直到有独立 `SPEC.md` 修订。
